## Journey: Game Engine → Memory Palace

### Game engine attempt (abandoned)
- WASD keyboard → `interact()` calls mapped to scenario prompts
- 3 scenarios: mountain climb, dungeon crawl, space walk
- **Didn't work well** — Odyssey is too imprecise for game-like controls
- From Odyssey team: model is bad at subtle movements, needs very detailed full-scene prompts
- `interact()` uses WebRTC data channel (not HTTP, won't show in Network tab)

### Memory Palace (current direction)
Mark's idea: AI-generated visual memory palace using Method of Loci. Pipeline:
1. **GPT-5.2** generates palace plan (rooms, mnemonics)
2. **Gemini 3 Pro** (`gemini-3-pro-image-preview`) generates vivid room images (base64 PNG)
3. **Odyssey I2V** animates images into living video via `startStream({ image, prompt })`
4. **Frontend UI harness** — reliable HTML for progress, navigation, text (not dependent on Odyssey)

Key decisions:
- Deterministic pre-built challenges, not freeform input
- Odyssey is the visual wow layer, not the core product
- Each room = full detailed scene (plays to model strengths)

## Gemini API ("Nano Banana Pro")
- SDK: `@google/genai` (NOT the deprecated `@google/generative-ai`)
- Model IDs: `gemini-2.5-flash-image` (fast/cheap) or `gemini-3-pro-image-preview` (pro, text rendering, 4K)
- Returns base64 PNG inline (not URLs) — convert to Blob for Odyssey I2V
- Works in browser (hackathon OK, production needs proxy)
- Pro model has "thinking" steps (adds latency, better quality)
- `imageSize` must use uppercase K: `"2K"` not `"2k"`
